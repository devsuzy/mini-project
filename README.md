# 카톡 채팅 → 액션 아이템

카카오톡 그룹채팅 CSV 를 올리면 **답변이 빠진 질문 · 공지하면 좋을 것 · 이슈 신호 · 반복 질문(FAQ)** 을 뽑아 방장에게 돌려주는 로컬 웹 도구.

수백 건씩 쌓인 대화를 위로 스크롤하며 "내가 놓친 질문 없나" 확인하는 일을 대신한다.

**대화가 이 컴퓨터 밖으로 나가지 않는다.** 로컬 Ollama 만 쓰므로 API 키도, 과금도, 외부 전송도 없다.

<br>

## 무엇을 뽑아주나

| 항목 | 내용 |
|---|---|
| **답변 안 된 질문** | 누가 언제 무엇을 물었는데 아무도 답하지 않았는지 + 방장이 할 일 한 줄 |
| **공지하면 좋을 것** | 결정 사항, 자료 위치, 확정된 일정처럼 고정해두면 반복 설명이 줄어들 내용 |
| **이슈 신호** | 반복되는 피로·불편 호소, 사람 사이의 마찰, 광고·스팸 (`즉시` / `지켜보기` / `참고`) |
| **반복 질문 (FAQ)** | 서로 다른 사람이 여러 번 물어본 질문 + 대화에 이미 나와 있던 답 |
| **요약** | 이 기간에 무슨 일이 있었는지 몇 문장 |

항목마다 체크박스가 있어 처리한 것을 지워가며 쓸 수 있고, **마크다운으로 복사** 버튼 한 번이면
결과를 그대로 공지에 붙여넣을 수 있다.

<br>

## 시작하기

### 1. Ollama 설치 후 모델 받기

```bash
brew install ollama
brew services start ollama      # 또는: ollama serve
ollama pull qwen2.5:7b          # 약 4.7GB
```

### 2. 실행

```bash
npm start                       # → http://localhost:5178
```

**`npm install` 은 필요 없다 — 의존성이 0개다.** Node 20.12 이상만 있으면 된다
(전역 `fetch` 와 `--env-file-if-exists` 플래그를 쓴다).

서버가 뜰 때 Ollama 상태를 같이 확인해서, 안 떠 있거나 모델이 없으면 터미널에 무엇을 하면 되는지 알려준다.

<br>

## 쓰는 법

1. **CSV 를 끌어다 놓는다** — 카카오톡에서 내보낸 `Date,User,Message` 형식의 파일
2. **내 이름(방장)을 적는다** — 할 일 문장의 주어가 된다
3. **기간을 고른다** — 데이터가 많으면 기본값이 최근 7일로 잡힌다
4. **분석 시작**

첫 실행은 모델을 메모리에 올리느라 오래 걸린다. 진행률과 예상 시간이 표시된다.

> **처음이라면 `sample-chat.csv` 로 먼저 돌려보는 것을 권한다.** 실제 대화가 아닌 허구 데이터이고,
> 미답변 질문 3건과 반복 질문 3건이 일부러 심어져 있어서 도구가 무엇을 잡아내는지 바로 보인다.

### 카카오톡 CSV 내보내기

맥 카카오톡의 대화 내보내기는 CSV 를 만들어준다. 첫 줄이 `Date,User,Message` 면 맞는 파일이다.
윈도우·모바일에서 나오는 `.txt` 내보내기는 **아직 지원하지 않는다.**

<br>

## 결과를 믿을 수 있게 만든 장치

7B 급 로컬 모델은 그럴듯한 것을 지어낸다. 그래서 모델에게 통째로 맡기지 않는다.

- **규칙이 후보를 확정하고, 모델은 판정과 문장 다듬기만 한다.** 질문 탐지와 반복 질문 묶기는
  코드가 하고, 모델은 그 목록 안에서만 고를 수 있다. 목록에 없는 항목을 만들어내면 서버가 버린다.
- **걸러진 것을 펼쳐볼 수 있다.** `사진`·`이모티콘`·`ㅋㅋ` 같은 노이즈를 무엇을 왜 제외했는지
  UI 에서 확인할 수 있다 — 안 보여주면 오탐을 영영 발견하지 못한다.
- **모든 항목에 근거를 붙인다.** `원문 보기` 를 누르면 그 시각 앞뒤의 실제 대화가 펼쳐진다.
  지어낸 항목인지 바로 확인할 수 있다.
- **검증에서 탈락한 항목 수를 알려준다.** "결과가 없다" 와 "모델이 내놓았지만 전부 걸러졌다" 는
  다른 상황이라 구분해서 표시한다.

그래도 완벽하지 않다 — 아래 [알려진 한계](#알려진-한계)를 보라.

<br>

## 설정

`.env` 파일이나 환경변수로 바꾼다 (`.env.example` 참고).

```bash
PORT=3000 npm start                              # 포트
OLLAMA_MODEL=qwen2.5:14b npm start               # 더 큰 모델 (느리지만 정확)
OLLAMA_HOST=http://다른호스트:11434 npm start      # 원격 Ollama
```

| 변수 | 기본값 |
|---|---|
| `PORT` | `5178` |
| `OLLAMA_HOST` | `http://127.0.0.1:11434` |
| `OLLAMA_MODEL` | `qwen2.5:7b` |

<br>

## 성능

로컬 `qwen2.5:7b`, M 시리즈 맥 기준 실측.

| 대화량 | 소요 시간 |
|---|---|
| 30건 | 30초 |
| 34건 | 44초 |
| 396건 (12일치) | 236초 |

대략 6,000자마다 한 번씩 모델을 부르고, 한 번에 50~60초가 걸린다.
2만 건짜리 파일 전체는 30분이 넘으므로 **기간을 좁혀서 쓰는 것을 전제로 만들었다.**

<br>

## 프라이버시

- 서버는 **`127.0.0.1` 에만 바인딩한다.** 같은 Wi-Fi 의 다른 기기에서 열 수 없다.
- 대화는 브라우저 → 로컬 서버 → 로컬 Ollama 까지만 간다. 외부로 나가는 요청이 없다.
- `.gitignore` 가 `KakaoTalk_Chat_*` 등 **실제 대화 파일 패턴을 막는다.** 남의 대화는 커밋되면
  되돌릴 수 없다. 개발·테스트에는 허구 데이터인 `sample-chat.csv` 를 쓴다.

<br>

## 개발

```bash
./test/run.sh          # 파서·필터·탐지·병합 단위 테스트 (모델 불필요, 1초)
node test/e2e.js       # 실제 모델까지 태우는 종단 테스트 (~45초)
node --check server.js # 문법 검사 — 빌드 단계가 없다
```

`index.html` 은 요청마다 디스크에서 읽으므로 **HTML 을 고쳐도 서버를 재시작할 필요가 없다.**

구조와 설계 배경(카톡 CSV 의 함정, 프롬프트가 지금 모양인 이유, 필드를 추가할 때 함께 고쳐야 하는 곳)은
[`CLAUDE.md`](CLAUDE.md) 에 정리해두었다.

```
브라우저 (index.html)              server.js :5178        Ollama :11434
 CSV 파싱 → 필터 → 청킹  ─청크씩→   프롬프트 조립  ──→   qwen2.5:7b
 진행률·병합·렌더      ←────────  {요약,질문,공지,이슈,FAQ}
```

CSV 파싱·노이즈 필터·질문 탐지·청킹·병합은 전부 브라우저에서 한다 — 2만 줄 파일을 통째로
서버에 올리지 않기 위해서다. `server.js` 는 정적 서빙과 Ollama 프록시만 한다.

<br>

## 알려진 한계

- 카카오톡 **`.txt` 내보내기는 지원하지 않는다.** CSV 전용이다.
- 7B 모델이라 **같은 정보가 실행마다 다른 칸에 담길 수 있다.** 계약서 위치가 어떤 때는
  FAQ 의 답으로, 어떤 때는 공지 후보로 간다. 정보가 사라지지는 않지만 자리가 흔들린다.
- 할 일 문장의 주어가 **가끔 방장이 아닌 질문자로 샌다** (12건 중 3건 정도).
- **분석을 시작하면 중간에 멈출 수 없다.** 4청크짜리면 4분을 기다려야 한다.
- 미디어로만 응답된 질문을 내부적으로 "불확실" 로 다루는데, 아직 UI 에서 구분해 보여주지 않는다.
